# Program-Scoped school_admin — Access Model

**Status:** Design approved, pending implementation plan
**Date:** 2026-06-18

## Goal

Today `school_admin` is tenant-wide (identical to `admin`) for the school collections. Scope it to **only the programs it has been assigned**: once a school_admin is granted a program, they get full access to everything inside it (classes, sessions, enrollments, students, attendance) — and nothing in programs they weren't granted.

`teacher` (class-scoped) and `admin` (tenant-wide) are already correct and unchanged. `staff` stays tenant-wide read-only. `platformOwner` unchanged.

## Assignment

Add **`managedPrograms`** to the Users collection: a `hasMany` relationship to `terms`, shown when `role === 'school_admin'`. Set by an admin/platformOwner (creating a program is admin-only; granting it to a school_admin is how they get access). It lives on the user record, so it's available as `req.user.managedPrograms` in every access check **without a query**. One additive migration (`users_managed_programs` join table).

## Scoping helpers (`src/access/schoolAccess.ts`)

Parallel to the existing async `teacher*` helpers, keyed off `managedPrograms`:

- `managedProgramIds(user)` — read `user.managedPrograms` (ids or populated objects → normalized ids). Pure (no query).
- `schoolAdminClassIds(req)` — query `school-classes where term ∈ managedProgramIds` → class ids.
- Six resolvers returning a Payload `where`:
  - **Terms** → `{ id: { in: managedProgramIds } }`
  - **Classes** → `{ term: { in: managedProgramIds } }`
  - **Sessions** → `{ class: { in: schoolAdminClassIds } }`
  - **Enrollments** → `{ class: { in: schoolAdminClassIds } }`
  - **Students** → students who are actively enrolled in those classes **or** whose `registeredProgram ∈ managedProgramIds`: `{ or: [{ id: { in: enrolledStudentIds } }, { registeredProgram: { in: managedProgramIds } }] }`
  - **Attendance** → `{ session: { in: sessionIds } }` (sessions of their classes)

A school_admin with **no** managed programs resolves to an empty `in: []` (matches nothing) — never tenant-wide.

## Access composition (refactor)

Pull `school_admin` out of the tenant-wide path:
- `schoolTenantRead` → platformOwner all; **admin/staff** tenant-scoped; else false (was: included school_admin).
- `schoolTenantWrite` → platformOwner all; **admin** tenant-scoped; else false (was: included school_admin).
- Two new wrappers compose the role branches so each collection stays one line:
  - `readByRole({ teacher, schoolAdmin })`: platformOwner → true; teacher → teacher resolver; school_admin → schoolAdmin resolver; else → `schoolTenantRead` (admin/staff tenant read).
  - `writeByRole({ teacher, schoolAdmin })`: platformOwner → true; teacher → teacher resolver (where provided); school_admin → schoolAdmin resolver; else → `schoolTenantWrite` (admin only).

Each collection's `read`/`update` use these with its teacher + schoolAdmin resolvers. The existing `denyKioskManager(...)` wrap stays.

## Create + guards

`create` returns a boolean (no `where`), so school_admin creates are gated by a boolean **and** enforced by a `beforeValidate` guard that rejects a record targeting a program they don't manage:

- **Terms**: create/delete = **admin/platformOwner only** (`schoolTenantCreate` minus school_admin). A school_admin cannot create or delete programs.
- **Classes**: create = platformOwner/admin (tenant) or school_admin (with ≥1 managed program). Guard `assertSchoolAdminScope` (collection `school-classes`): for a school_admin, `data.term` must be ∈ managedPrograms.
- **Enrollments**: create = same shape. Guard: resolve `data.class` → its `term`; must be ∈ managedPrograms.
- **ClassSessions**: auto-generated by the hook (overrideAccess bypasses access+guards). Manual create allowed for admin; school_admin manual create guarded by `data.class` → term ∈ managed.
- **AttendanceRecords**: the existing `assertTeacherOwnsSession` beforeValidate is generalized to `assertSessionScope` — for a teacher, session's class must list them; for a school_admin, the session's class's `term` must be ∈ managedPrograms; admin/platformOwner bypass.
- **Students**: create = platformOwner/admin/school_admin (with managed programs). No program guard on create (a student isn't owned by a program); the wizard's "Add new student" tags `registeredProgram` with the current program, so the created student stays visible to the school_admin. Update/delete are scoped by the read resolver.

Delete: school_admin delete uses the same program-scoped `where` as update (their records only); Terms delete admin-only.

## UI fallout (mostly free)

- **Program picker** fetches `/terms` under access → a school_admin automatically gets only their managed programs; no picker change needed.
- **"+ New program"**: hide for non-admins (school_admin can't create programs). The wizard create-mode (`?program=new`) and the picker's "+ New program" item render only for `platformOwner`/`admin`. A school_admin opening setup edits one of their programs.
- **Dashboard / Classes / Students / Attendance**: queries are access-scoped, so they return only the school_admin's data automatically — no per-view changes.
- **Class-detail "Enroll a student" catch-all**: its student list is access-scoped now, so for a school_admin it already only shows students in their scope (no leak).

## Migration

`managedPrograms` (hasMany select/relationship) → `users_managed_programs` join table. Additive; generated with `npx payload migrate:create`, applied by the user.

## Testing

- **`managedProgramIds`** — normalizes ids/objects/empty.
- **The six school_admin resolvers** — produce the right `where`; empty managed → `in: []`; mock `req.payload.find` for class/session/enrollment id resolution (same style as the teacher-helper tests).
- **`readByRole`/`writeByRole`** — branch correctly for platformOwner/admin/school_admin/teacher/staff/none.
- **Guards** — `assertSchoolAdminScope`/`assertSessionScope` throw when a school_admin targets a program they don't manage; pass when they do; admin/platformOwner bypass.
- Per-collection access tests extended: a school_admin with managed `[P1]` reads/writes only P1's classes/sessions/students/attendance; cannot create a class in `P2`; cannot create/delete a program.

## Non-goals

- Changing `staff` (stays tenant-wide read-only) or `admin`/`teacher`.
- Per-class (sub-program) grants to a school_admin — they get the whole program.
- FormSubmissions access for school_admin (stays denied; registration is handled by the hook).
- A UI for bulk-assigning programs beyond the Users edit page.
